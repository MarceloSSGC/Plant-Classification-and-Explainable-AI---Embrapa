Proposta:

0. View da Proposta:

- (Multi view) A entrada (imagem multiespectral) é dividida em três visões restritas;
- (Backbone) Modelo 1 recebe multiview e prediz multioutput (vários conceitos/características);
- (Conceitos) Saídas do modelo 1 são características semânticas chamadas de conceitos;
- (Classificação) Modelo 2 recebe características semânticas e classifica imagem;
- (XAI) Interpretabilidade da predição e auditoria do modelo;


1. Arquitetura Multi-View

A proposta aborda a explicabilidade em Deep Learning para o reconhecimento de plantas daninhas por meio de um modelo 
intrinsicamente interpretável. A entrada de 5 bandas multiespectrais é dividida em três visões restritas (views), 
garantindo o isolamento das fontes físicas de informação:

- View Espectral / Cor: Captura unicamente a resposta de reflexância radiométrica, restrita ao domínio espacial .
- View de Textura: Extrai padrões locais de variação espacial e frequências (como nervuras e rugosidade), com a 
intensidade de cor normalizada.
- View de Forma (Shape): Binariza ou isola estritamente a morfologia e os contornos da folha, omitindo o conteúdo 
interno para evitar o vazamento de textura ou cor.

(Podem ser outros views, mas vamos começar com esses 3)

2. Backbone e Camada Conceitual (CBM - Concept Bottleneck Model)

Sobre as representações geradas pelas três views, um modelo de médio/grande porte (Backbone), que chamaremos de modelo 1, é usado 
para incorporar os diferentes views, processar e gerar os conceitos/características (multioutput). Os conceitos são interpretáveis e 
alinhados à taxonomia botânica (por exemplo: folha alongada, nervuras salientes, margem serrilhada, coloração avermelhada),
eles formam a primeira base de interpretação.

3. Predição da Classe:
Com os conceitos aprendedos um segundo modelo de pequeno porte, modelo 2, será usado para receber os conceitos e predizer a classe
(espécie da planta).
Uma alternativa é, ao invés de treinar dois modelos separadamente, como estamos propondo, uma opção  seria treinar ambos modelos 
juntos,com a diferente que o modelo 1 tenha como saída os conceitos + vetor de embedding, o modelo 2 recebe conceitos + embedding
e classifica imagem.

4. Explicabilidade Hierárquica em Dois Níveis

A rede realiza a predição final da espécie com base na ativação desses conceitos, permitindo uma Explicabilidade Hierárquica em Dois 
Níveis via SHAP:

Nível 1 (View ➔ Conceito): Avalia a contribuição de cada view para a ativação de um conceito botânico específico.
Nível 2 (Conceito ➔ Predição): Avalia a contribuição de cada conceito ativado para a decisão final da espécie.
(Talvez também (View ➔ Predição))

6. Análise de Coerência Semântica e Integridade do Aprendizado

A relação entre a origem da informação (views) e o significado do conceito (CBM) permite questionar se o modelo realmente aprendeu a física 
e a biologia do problema ou apenas encontrou atalhos estatísticos (spurious correlations / shortcut learning).

Exemplo de Incoerência

"Se a View de Shape é responsável por $75\%$ da ativação do conceito de Pigmentação Avermelhada, o modelo não está utilizando as informações 
cromáticas da folha. Ele aprendeu um viés relacionado à morfologia como "atalho" para inferir a presença da pigmentação avermelhada, tornando 
a decisão frágil a variações de campo."

Exemplo de Coerência

Se para o conceito folha alongada, a View de Forma (Shape) contribui com $85\%$ do peso SHAP, confirma-se que a rede está utilizando o contorno 
e a geometria correta para fundamentar esse conceito morfológico.


7. Auditoria de Integridade Semântica: CVAR e CVCM

Para detectar e quantificar as inconsistências identificadas no Item 6, propõem-se duas métricas de auditoria:

- Razão de Alinhamento Conceito-View (CVAR)
O CVAR mede a proporção de contribuição via SHAP que um conceito individual $c$ recebe da view fisicamente pertinente a ele ($V_{\text{pertinente}}$) 
em relação à soma das contribuições de todas as views:

$$\text{CVAR}(c) = \frac{\text{Contribuição SHAP da } V_{\text{pertinente}} \text{ para o conceito } c}{\sum_{v \in \text{Views}} \text{Contribuição SHAP da view } v \text{ para o conceito } c}$$

- Concept-View Consistency Metric (CVCM)
A CVCM agrega o CVAR de todos os $K$ conceitos mapeados na camada CBM, consolidando uma métrica global de auditoria para o modelo:

$$\text{CVCM} = \frac{1}{K} \sum_{k=1}^{K} \text{CVAR}(c_k)$$

Uso como Auditoria (Sanity Checking): A CVCM serve como um diagnóstico de integridade. Um modelo pode atingir $95\%$ de acurácia, mas apresentar 
uma CVCM baixa (ex: $< 0.50$), o que auditoria e prova que a rede atinge alto desempenho apoiando-se em decisões incoerentes. Uma CVCM 
elevada (ex: $> 0.85$) garante que o modelo aprendeu as características corretas.

Vamos recaptular. Dado uma imagem IMG, eu posso aplicar 3 transformações (com algum filtro) e obter 3 views dessa imagem:
IMG -> T_1 -> View_1 (View de SHAPE, por exemplo)
IMG -> T_2 -> View_2 (View de Textura, por exemplo)
IMG -> T_3 -> View_3 (View de Cor/espectro, por exemplo)

O modelo preditivo (Parte I) vai receber como input o concatenado [View 1, View 2, View 3] e vai predizer algumas características de IMG:
C_11, C_12, ..., C_1a (De preferência características que usam como informações de entrada exclusivamente o View_1)
C_21, C_22, ..., C_2b (De preferência características que usam como informações de entrada exclusivamente o View_2)
C_31, C_32, ..., C_3c (De preferência características que usam como informações de entrada exclusivamente o View_3)

Eu gostaria que cada conjunto de características preditas, digamos C_21, C_22, ..., C_2b, quando se faz SHAP Values ou outro avaliador de contribuição, o 
view que mais contribui seja o View 2. Para acontecer esse comprtamente nos 3 níveis,  eu preciso escolher bem as transformações de cada input/View e 
quais serão as características. 

Objetivo:
Temos um problema de alinhamento entre views e grupos de alvos/características/conceitos, objetivo é maximizar a contribuição:
Contribuição(View_i -> C_i) > Contribuição(View_j -> C_i), para j diferente de i
